# Zm runtime and concurrency library

## Overview

Memory allocation, intrusive ownership and containers, synchronization, threads and scheduling, lifecycle management, diagnostics and runtime telemetry.

## Interface

- `libZm.la` builds heap support and the shared implementation list, installs Zm/Ztc headers, and links Zu plus configured platform libraries. [Makefile.am:libZm_la_SOURCES] [Makefile.inc:zm_common_sources]
- `ZmAlloc`, `ZmLocal` and `ZmScratch` choose stack or heap storage. `ZmAllocator` adapts heaps to STL allocators; `ZmHeapCacheT`, `ZmNHeap`, `ZmHeapMgr` and `ZmVHeap` provide fixed/variable-size caches, allocation policies and telemetry. [ZmAlloc.hh:ZmAlloc] [ZmLocal.hh:ZmLocal_] [ZmScratch.hh:ZmScratch_] [ZmAllocator.hh:ZmAllocator_] [ZmHeap.hh:ZmHeapCacheT] [ZmVHeap.hh:ZmVHeap_]
- `ZmAtomic` wraps integral/pointer atomics. Recursive/primitive/spin/read-write locks, lock traits/guards, conditions and semaphores provide synchronization; `ZmNoLock` provides explicit no-op policies. [ZmAtomic.hh:ZmAtomic] [ZmLock.hh:ZmLock] [ZmPLock.hh:ZmPLock] [ZmSpinLock.hh:ZmSpinLock] [ZmRWLock.hh:ZmRWLock] [ZmGuard.hh:ZmGuard] [ZmCondition.hh:ZmCondition] [ZmSemaphore.hh:ZmSemaphore] [ZmNoLock.hh:ZmNoLock]
- `ZmObject`/`ZmPolymorph` provide atomic intrusive counts; `ZmRef` owns references and `ZmContext` erases borrowed/owned object pointers. `ZmFn` delegates bind free/member functions, objects and stateful lambdas. [ZmObject.hh:ZmObject] [ZmPolymorph.hh:ZmPolymorph] [ZmRef.hh:ZmRef] [ZmContext.hh:ZmContext] [ZmFn_.hh:ZmFn] [ZmFn.hh:ZmLambda]
- `ZmHash` is a chained node table; `ZmLHash` stores values in linear-hash storage. Multi-index hashes share consolidated nodes. Single-/multi-index caches add loaders, pending-load coalescing, LRU eviction and statistics. [ZmHash.hh:ZmHash] [ZmLHash.hh:ZmLHash] [ZmPolyHash.hh:ZmPolyHash] [ZmCache.hh:ZmCache] [ZmPolyCache.hh:ZmPolyCache]
- Lists and red/black trees expose policy-controlled intrusive nodes; queues/stacks store values with sentinel holes. Node policies determine reference and deletion behavior. [ZmList.hh:ZmList] [ZmRBTree.hh:ZmRBTree] [ZmQueue.hh:ZmQueue] [ZmStack.hh:ZmStack] [ZmNode.hh:ZmNode_] [ZmNodeFn.hh:ZmNodeFn_]
- `ZmPQueue` is a deterministic skip-list queue of keyed run-length intervals, with overlap handling, directional iteration and span/gap queries. `ZmPQRx`/`ZmPQTx` add application-driven receive, resend, acknowledgement and archival state machines. [ZmPQueue.hh:ZmPQueue] [ZmPQueue.hh:ZmPQRx] [ZmPQueue.hh:ZmPQTx]
- `ZmRing` provides fixed/variable messages with single/multiple writers and readers; multi-reader mode broadcasts. Control/data/mirrored-memory helpers back it. `ZmRingFn` moves callable captures into ring storage; `ZmRingMirror` exposes explicit mapping lifecycle. [ZmRing.hh:ZmRing] [ZmRing.hh:MirrorMem] [ZmRingFn.hh:ZmRingFn_] [ZmRingMirror.hh:ZmRingMirror]
- `ZmThread` and contexts configure native threads, names, stack, priority, partition and affinity. `ZmTopology` wraps hwloc; `ZmBitmap` owns hwloc bitmaps. Platform helpers expose process/thread IDs, CPU count, aligned allocation and process exit. [ZmThread.hh:ZmThread] [ZmThread.hh:ZmThreadParams] [ZmTopology.hh:ZmTopology] [ZmBitmap.hh:Bitmap] [ZmPlatform.hh:Zm]
- `ZmScheduler` manages worker slots, rings, overflow queues and timers; `ZmEngine` supplies asynchronous/blocking start/stop transitions. `ZmBlock` waits for callback completion, including indexed fan-out. [ZmScheduler.hh:ZmScheduler] [ZmEngine.hh:ZmEngine] [ZmBlock.hh:ZmBlock]
- Cleanup levels order global destruction. `ZmGlobal`, `ZmSingleton`/`ZmStatic` and `ZmSpecific`/`ZmTLS` provide global and thread-local instances with optional finalization. [ZmCleanup.hh:ZmCleanup] [ZmGlobal.hh:ZmGlobal] [ZmSingleton.hh:ZmSingleton] [ZmSpecific.hh:ZmSpecific]
- Realtime clock/sleep, interval statistics, randomized backoff and scheduler-backed timeouts support timing. Mersenne Twister generators are instance-based or thread-local. [ZmTime.hh:now] [ZmTime.cc:sleep] [ZmTimeInterval.hh:ZmTimeInterval] [ZmBackoff.hh:ZmBackoff] [ZmTimeout.hh:ZmTimeout] [ZmRandom.hh:ZmRandom] [ZmRandom.cc:ZmRand]
- Assertions, backtrace capture/symbolization, trace rings, demangling, reference-debug hooks and process traps provide diagnostics. Codec callback adapters allocate temporary output around Zu codecs. [ZmAssert.hh:ZmAssert] [ZmBackTrace_.hh:ZmBackTrace] [ZmBackTracer.hh:ZmBackTracer] [ZmDemangle.hh:ZmDemangle_] [ZmObjectDebug.hh:ZmObjectDebug] [ZmTrap.hh:ZmTrap] [ZmCodec.hh:ZmCodec_Fn]
- Ztc hash/heap/thread/queue interfaces expose telemetry, manager watchers, CSV output and tuning calculations; RAG values summarize utilization. [ZtcHash.hh:HashMgr] [ZtcHeap.hh:HeapMgr] [ZtcThread.hh:ThreadMgr] [ZtcQueue.hh:QueueMgr] [ZtcTypes.hh:RAG]

## Invariants

- Container locking is a template policy and commonly defaults to `ZmNoLock`. Raw returned pointers do not retain operation guards. Many iterators hold a lock for their lifetime; unlocked counters are named explicitly. Linear-hash edits can relocate values. [ZmHash.hh:ZmHash_Defaults] [ZmLHash.hh:Iter_] [ZmList.hh:Iter] [ZmQueue.hh:ZmQueue_Unlocked]
- Shadow nodes are unmanaged; owning object nodes use intrusive references while ordinary owned nodes use deletion-capable removal references. Secondary multi-index nodes are shadows over primary-owned objects. Callers must not insert nodes with conflicting links or ownership. [ZmNodeFn.hh:ZmNodeFn_] [ZmPolyHash.hh:ZmPolyHash_NodeT_] [ZmRBTree.hh:ZmRBTree_NodeExt]
- Atomic object counts start at zero. `acquire` adopts a count and `release` transfers it; copies increment and moves clear the source. `withRef` acquires only a positive count. A `ZmRef` can also wrap single-threaded Zu objects, so its name alone does not establish atomic counting. [ZmObject.hh:withRef] [ZmPolymorph.hh:withRef] [ZmRef.hh:acquire] [ZmRef.hh:release]
- Type-erased contexts use pointer bit 63 as an ownership discriminator; tree nodes also pack color into parent bit 63. These representations assume that bit is available. Context casts are unchecked. [ZmContext.hh:ZmContext] [ZmRBTree.hh:ZmRBTree_NodeExt]
- Cache-hit and eviction callbacks execute under the configured cache lock; loaders and completed-load callbacks execute unlocked. Traversals snapshot references before callbacks. Cache moves are initialization-only and unlocked. Multi-key eviction rejection does not enforce a hard capacity limit. [ZmCache.hh:find] [ZmPolyCache.hh:findMiss_] [ZmPolyCache.hh:ZmPolyCache]
- Hash insertion can allow duplicates. Tree unique mode suppresses duplicate chains but does not reject equal-key insertion; key-based tree deletion uses the read-guard path. Do not infer stronger uniqueness or write-lock guarantees from policy names. [ZmHash.hh:add] [ZmRBTree.hh:ZmRBTree_Defaults] [ZmRBTree.hh:del]
- Stack/heap-selection macros may evaluate sizes more than once. Scratch capacity is fixed and bare `push()` exposes unconstructed storage. Sized heap freeing requires the original size; prefixed allocations pair with `vfree`. Sharded arenas assume no contention and do not search other partitions. [ZmAlloc.hh:ZmAlloc] [ZmScratch.hh:push] [ZmVHeap.hh:free] [ZmHeap.cc:ZmHeapCache::init]
- Priority-queue interval arithmetic checks representability; overlap-disabled operation relies on compatible caller intervals. Span/gap callbacks run under a read guard. Explicit `verify` checks structure but is not automatically run after edits. Clean preserves sequence bounds/statistics, while reset changes bounds. [ZmPQueue.hh:endOf_] [ZmPQueue.hh:verify_] [ZmPQueue.hh:spans] [ZmPQueue.hh:clean_]
- Ordered Tx cursor restoration requires stopped, drained work and valid cursor order. Ordered acknowledgements are cumulative; unordered acknowledgements remove exact-start nodes. Resend callbacks reprocess logical data and must not reuse protocol packet numbers. [ZmPQueue.hh:txRestore] [ZmPQueue.hh:ackd] [ZmPQueue.hh:resend]
- Ring operations require the corresponding open mode. Multi-reader mode requires variable-message sizing and an attached reader ID, with at most 62 read handles. Copying creates non-owning shadow views; owners outlive them. Ring operations manage raw bytes rather than message constructors/destructors. [ZmRing.hh:Ring] [ZmRing.hh:RingExt] [ZmRing.hh:push2]
- Linux mirrored-memory paths use private mappings, so this implementation does not establish shared-write mirroring. The standalone `ZmRingMirror` requires explicit close and has partial-failure cleanup limitations. [ZmRing.cc:MirrorMem::open] [ZmRingMirror.cc:open] [ZmRingMirror.hh:ZmRingMirror]
- Scheduler slots are 1..nThreads; zero selects a shared non-isolated worker where supported. Untargeted work can be dropped when no shared worker exists. `invoke` can run synchronously on the target worker; `run` schedules and `push` omits waking. Timer polling includes deadlines through now+quantum. [ZmScheduler.hh:invoke] [ZmScheduler.cc:tryPush_] [ZmScheduler.cc:work]
- Engine destruction requires Stopped. Application start/stop hooks eventually report completion; failed stop completion still transitions to Stopped unless a queued start launches. Timeout objects borrow their scheduler and capture their own address, so their lifetime must cover scheduled work. [ZmEngine.hh:ZmEngine] [ZmTimeout.hh:ZmTimeout]
- Thread-local instance iteration pins objects while invoking callbacks unlocked; it does not synchronize their contents. `ZmThreadContext::self` must not be called during exit. Process trap registration is intended once at startup and is not thread-safe. Random generators are explicitly unsuitable for cryptography. [ZmSpecific.hh:ZmSpecific_] [ZmThread.hh:self] [ZmTrap.hh:trap] [ZmRandom.hh:ZmRandom]

## Side Effects

- Heap managers allocate aligned or CPU-bound regions, recycle uninitialized payloads, update counters and invoke optional debug/watcher callbacks. Allocation failure invokes a shared handler and retries or aborts. Scratch/local destruction destroys values, updates per-thread allocation counters and frees heap backing. [ZmHeap.cc:ZmHeapCache::init_] [ZmHeap.hh:ZmHeapAlloc] [ZmScratch.hh:~ZmScratch_] [ZmLocal.hh:ZmLocal_]
- Containers allocate, move, relink and destroy values/nodes. Hash growth rebuilds buckets; cache loads coalesce work and update statistics/LRU state. Priority-queue overlap handling invokes clipping/writing hooks and can replace retained intervals. [ZmHash.hh:addNode_] [ZmLHash.hh:ZmLHash_] [ZmCache.hh:find] [ZmPQueue.hh:add_]
- Locks and semaphores block/wake native threads. Condition wait releases and reacquires the associated lock. Blocking adapters wait on thread-local semaphores; callbacks must provide the expected completion posts. [ZmCondition.hh:wait] [ZmSemaphore.hh:wait] [ZmBlock.hh:ZmBlock]
- Scheduler startup creates workers; dispatch retains callable/object state and overflow can allocate. Stop signals/wakes and joins workers, with asynchronous handling when requested from a worker. Queued ring invocation catches callable exceptions and destroys stored captures. [ZmScheduler.cc:start__] [ZmScheduler.cc:stop] [ZmRingFn.hh:invoke]
- Thread startup configures native resources and affinity, publishes telemetry and executes user code. Affinity/priority failures can log diagnostics; POSIX startup disables cancellation. Context telemetry and printing update CPU-sampling baselines. [ZmThread.cc:run_] [ZmThread.cc:bind] [ZmThread.hh:cpuUsage]
- Ring open/close manages allocations, mappings, backing handles and blockers. Publication/consumption changes counters and wake state; reset clears bytes/statistics, EOF stops new pushes, and multi-reader close detaches its reader. [ZmRing.cc:CtrlMem::open] [ZmRing.cc:MirrorMem::open] [ZmRing.hh:push2] [ZmRing.hh:reset]
- Global registration installs an atexit handler; cleanup deletes instances in ascending cleanup-level and reverse registration order. Singleton replacement and TLS retirement invoke optional finalization and release objects. TLS key-allocation failure reports to stderr and aborts. [ZmGlobal.cc:ZmGlobal_atexit] [ZmSingleton.hh:instance_] [ZmSpecific.hh:dtor_] [ZmSpecific.cc:ZmSpecific_allocFail]
- Automatic random seeding reads OS entropy or falls back to time. Sleep blocks; Windows clock calibration changes priority/affinity. Timeout callbacks run under the timeout lock and can reschedule work. [ZmRandom.hh:seed] [ZmTime.cc:sleep] [ZmTimeout.hh:work]
- Backtrace symbolization reads/caches module data, allocates and writes supplied streams. Assertions log then abort. Trap setup installs process handlers; logging writes stderr or Windows Event Log. Debug reference tracking allocates backtraces. [ZmBackTrace.cc:ZmBackTrace_Mgr] [ZmAssert.cc:ZmAssert_fail] [ZmTrap.cc:trap] [ZmTrap.cc:log] [ZmObjectDebug.cc:debug]
- Telemetry managers synchronize registry access and can invoke watchers under registry locks; capture delivery occurs after snapshotting. CSV/tuning output writes streams and may allocate temporary trees. [ZmHashMgr.cc:ZmHashMgr_] [ZmHeap.cc:capture] [ZmThread.cc:ZmThreadMgr_] [ZtcHash.cc:HashTuneCSV_print] [ZtcHeap.cc:HeapTuneCSV_print]
