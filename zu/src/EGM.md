# Zu foundation library

## Overview

Low-level types, compile-time reflection, containers and borrowed views, numeric and text codecs, time values, ownership helpers, and the TAP test framework.

## Interface

- `libZu.la` installs public C++ and C headers and compiles time/date, UTF, demangling, test-manager and C-wrapper implementations. MinGW separately builds the UTF-8 manifest object for executable linkage. [Makefile.am:libZu_la_SOURCES] [ZuUTF8.manifest:activeCodePage]

Type traits, normalization, deduction, alignment/size selection, derivation and element storage extend these facilities. [ZuLib.hh:ZuDecay] [ZuTraits.hh:ZuTraits] [ZuNorm.hh:ZuNorm] [ZuDeduce.hh:ZuDeduce] [ZuMostAligned.hh:ZuMostAligned] [ZuLargest.hh:ZuLargest] [ZuDerive.hh:ZuDerive] [ZuElem.hh:Z_]

[ZuTL.hh:ZuTypeList] [ZuSeq.hh:ZuSeq] [ZuSwitch.hh:dispatch] [ZuUnroll.hh:all] [ZuInvoke.hh:ZuInvoke] [ZuLambdaTraits.hh:ZuLambdaTraits] [ZuPP.hh:ZuPP_Eval] [ZuReserved.hh:ZuIfReserved]

## Invariants

- Borrowed spans, transformed arrays, string adapters, print wrappers, reference tuples and token slices do not extend backing-object lifetimes. Type-erased arrays capture length and callbacks; mutation requires a valid setter, even when the wrapper type permits mutation. Indexing is generally unchecked. [ZuSpan.hh:ZuSpan] [ZuMArray.hh:ZuMArray] [ZuVArray.hh:Array] [ZuTuple.hh:ZuFwdTuple] [ZuVStream.hh:ZuVStreamBuf]
- Fixed arrays require capacity between 1 and 65534. Many append/length paths clamp, but bare `push()` returns unconstructed storage. `span()` exposes capacity while `cspan()` exposes used length. Ordinary copying need not terminate strings; `terminate()` can shorten the used length. Splice callbacks must respect supplied storage and report actual usage. [ZuArray.hh:push] [ZuArray.hh:span] [ZuArray.hh:terminate] [ZuArray.hh:splice]
- Structural strings have fixed length N-1 and expose mutable backing despite their immutable-string description. Tuple physical storage order can differ from logical element order. Reflection preserves skipped metadata but filters it from active object operations; read-only setters are no-ops. [ZuString.hh:ZuString] [ZuTuple.hh:TupleBaseT_] [ZuStruct.hh:ZuActiveFields]
- Union reads require the matching discriminator; `ptr` reports mismatch with null. `new_`, `type_` and `null` are low-level lifetime operations: callers preserve tag/storage agreement. `null` destroys the active value and resets the tag without constructing alternative zero. Moves retain the source tag. [ZuUnion.hh:p] [ZuUnion.hh:new_] [ZuUnion.hh:type_] [ZuUnion.hh:null]
- Intrusive counts are plain non-atomic integers starting at zero. Objects must follow heap-allocation and positive-count conventions; acquire/release transfer reference responsibility without the usual increment/decrement. [ZuObject.hh:ZuObject] [ZuRef.hh:acquire] [ZuRef.hh:release]
- Primitive boxes use comparator-specific nulls; their arithmetic follows primitive behavior. Decimal checked arithmetic propagates null and detects overflow/division by zero, but raw access and constructors do not universally enforce documented bounds. Fixed-point values retain scale in their hash. [ZuBox.hh:ZuBox__] [ZuDecimal.hh:ZuDecimal] [ZuFixed.hh:hash]
- Numeric scanners consume prefixes and do not uniformly validate overflow or preserve outputs on failure. They do not establish strict bounded-read safety for every fractional/hex path. Numeric printers require caller-provided capacity and usually do not terminate output. [Zu_aton.hh:Zu_nscan_] [Zu_ntoa.hh:Zu_nprint] [Zu_ntoa.hh:Zu_vprint]
- Base and hex codecs require adequate destination capacity; decoding stops at invalid input/padding and supports in-place operation. Bit-stream operations require caller availability and valid bit counts. Bitfield indices are unchecked and assigned values are not masked to field width. [ZuBase64.hh:decode] [ZuBase32.hh:decode] [ZuHex.hh:decode] [ZuBitStream.hh:out] [ZuBitfield.hh:set]
- UTF conversion stops on decode failure or output exhaustion; its overflow flag reports insufficient output capacity. UTF-8 decoding checks leading shape/length but does not enforce all continuation-byte or Unicode scalar constraints. Width calculation uses the implemented range table and returns one or two columns. [ZuUTF.hh:ZuUTF8] [ZuUTF.hh:cvt_overflow] [ZuUTF.cc:width]
- Fixed bitmap lengths round up to complete 64-bit words; range ends are exclusive. C bitmap allocation callbacks own variable storage, and growth can replace the pointer. The current C copy implementation computes its byte count from bit length incorrectly, so it does not provide a safe nonempty-copy contract. [ZuBitmap.hh:Data] [ZuBitmap.hh:set] [zu_bitmap.cc:zu_bitmap_resize] [zu_bitmap.cc:zu_bitmap_copy]
- Date/time validity uses sentinel fields; raw component access need not normalize. Parsers accept prefixes and do not enforce month-specific day limits. Calendar reformation is process-global, explicitly initialization-only and unsynchronized. Reused date-format objects contain mutable caches. [ZuTime.hh:operator *] [ZuDateTime.hh:reformation] [ZuDateTime.cc:eov] [ZuDateTime.hh:csv_print]
- Binary/interpolation search requires sorted input. Packed semantic versions contain only numeric major/minor/patch components; scanning validates bounded components and preserves the old value on failure. Matcher tables require fewer than 256 keys. [ZuSearch.hh:ZuSearch] [ZuSemVer.hh:scan] [ZuMatcher.hh:ZuMatcher]
- The TAP manager is single-threaded, relies on balanced scopes and static registration, and finalizes its registration list once. [ZuTest.hh:ZuTestMgr] [ZuTest.cc:init] [ZuTest.cc:end_]

## Side Effects

- Container edits construct, destroy and move elements and can invoke supplied accessors, comparison functions and splice callbacks. Sorting reorders caller storage. Ownership wrappers decrement counts or delete objects on replacement/destruction. [ZuArrayFn.hh:ZuArrayFn_Ops] [ZuSpan.hh:splice] [ZuSort.hh:ZuSort] [ZuRef.hh:ZuRef] [ZuPtr.hh:ZuPtr]
- Guards invoke uncancelled callbacks at destruction; move assignment can first invoke the destination guard. Explicit memory clearing overwrites supplied storage. Placement construction and stack-allocation helpers affect caller storage/stack. [ZuLib.hh:ZuGuard] [ZuLib.hh:ZuClear] [ZuLib.hh:ZuNew]
- Text codecs and printers write caller buffers or streams. Percent decoding compacts and zeroes input and may partially mutate before failure. Bounded streams advance their view and can truncate direct appends; they do not add a terminator. Type-erased stream callbacks must consume temporary arguments synchronously. [ZuPercent.hh:decode] [ZuStream.hh:append] [ZuVStream.hh:operator <<]
- Numeric/date scans overwrite destinations, including null on failure on the documented paths. C wrappers write supplied structs and buffers. Calendar setters and formatter caches mutate shared or retained state; default date and C time printing use thread-local formatters. [ZuDecimal.hh:scan] [ZuDateTime.cc:scan] [ZuDateTime.cc:reformation] [zu_time.cc:zu_time_out_csv]
- C bitmap allocation, resize and deletion invoke allocator/free callbacks. Growth failure can free old storage; callers must honor each function's returned pointer and failure behavior. Parsing overwrites the output pointer without freeing a prior allocation. [zu_bitmap.cc:zu_bitmap_resize] [zu_bitmap.cc:zu_bitmap_delete] [zu_bitmap.cc:zu_bitmap_in]
- Demangling owns and frees ABI buffers when successful and otherwise borrows the input symbol. Registering a transform replaces process-global callbacks and invokes the previous finalizer without synchronization. [ZuDemangle.hh:ZuDemangle_] [ZuDemangle.cc:transformFn]
- TAP registration/contexts allocate storage; execution prints and flushes TAP output, invokes callbacks and can exit with the failure count. Test utility argument handling reads `HARNESS_ACTIVE`, changes global verbosity, writes stderr and can exit on invalid arguments. [ZuTest.cc:init] [ZuTest.cc:end_] [ZuTestUtil.hh:parse]
