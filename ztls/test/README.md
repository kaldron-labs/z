# Ztls tests

The first run of `ZtlsX25519Test`, `ZtlsHybridTest`, `ZtlsHPKETest`, or
`ZtlsAgeTest` runs `ZtlsTestKeygen` to create the X25519, hybrid, RSA and
Ed25519 test identities. The Go fixture helper uses those keys to produce
independent reference outputs for key agreement, HPKE, age and OpenSSH.
First use requires Go 1.25 or later and the modules pinned in
`keyfixture/go.mod`. For offline setup, populate the Go module cache in
advance with `go -C ztls/test/keyfixture mod download`.

The helper publishes the complete fixture set in the build directory under
`.ztls-test-keys-v1/`. Subsequent runs read it directly. Removing that
directory generates fresh keys on the next run. The age tests cover nineteen
reference cases, including hybrid/classical headers, recipient selection,
unknown stanzas, non-canonical encodings, low-order shares, scrypt limits
and stream termination. They also decrypt reference-age ciphertexts with
locally generated RSA and Ed25519 identities in OpenSSH format.

`ZtlsVaultTest` is the vault TAP entry point. It covers the application API,
the in-memory `Ephemeral` store, the JSON `File` aggregate, and `Indirect` with
both stores. The encrypted-file test independently opens the account-hash
`.age` file through `ZtlsAge` using the passphrase stored by `File`. It also
checks separate accounts under one home. `libZtlsVaultFixture` exercises
`Module` with both `Direct` and `Indirect`. Native Secret Service cases run in
`ztls/itest` and `ztls/interop`. On Linux, the suite checks the aggregate
directory/file permissions, forks a contender to check PID-file exclusion,
and recovers after a holder exits without `close()`. Run it directly as
`./ztls/test/ZtlsVaultTest` from the repository root.

To exercise ML-KEM-768 PEM interoperability with the OpenSSL CLI in the
current build configuration, run from the repository root:

```sh
dir=$(mktemp -d)
./ztls/test/ZtlsKEMTest --save "$dir/z-private.pem" "$dir/z-public.pem"
openssl pkey -in "$dir/z-private.pem" -noout
openssl pkey -pubin -in "$dir/z-public.pem" -noout
openssl genpkey -algorithm ML-KEM-768 -out "$dir/openssl-private.pem"
openssl pkey -in "$dir/openssl-private.pem" -pubout -out "$dir/openssl-public.pem"
./ztls/test/ZtlsKEMTest --load "$dir/openssl-private.pem" "$dir/openssl-public.pem"
```

`ZtlsX25519Test` checks X25519 agreement against Go and covers RFC 8410 DER/PEM
round-trips. To check X25519 PEM interoperability in both directions:

```sh
dir=$(mktemp -d)
./ztls/test/ZtlsX25519Test --save "$dir/z-private.pem" "$dir/z-public.pem"
openssl pkey -in "$dir/z-private.pem" -noout
openssl pkey -pubin -in "$dir/z-public.pem" -noout
openssl genpkey -algorithm X25519 -out "$dir/openssl-private.pem"
openssl pkey -in "$dir/openssl-private.pem" -pubout -out "$dir/openssl-public.pem"
./ztls/test/ZtlsX25519Test --load "$dir/openssl-private.pem" "$dir/openssl-public.pem"
```

The temporary directories contain private-key material; remove them after
the interop checks using the platform's appropriate secure workflow.

`make -C ztls/interop ztlsageinterop` builds the optional Age interoperability
driver; it is not part of the TAP test target. It accepts
`encrypt|decrypt`, one of `x25519|hybrid|scrypt|ssh-rsa|ssh-ed25519`, a key
file, an input file, and an output file. SSH decryption also takes an SSH
authorized-key public file as the final argument. Native key files may be
generated by `age-keygen` (use `-pq` for hybrid); SSH public files use the
ordinary `ssh-rsa` or `ssh-ed25519` authorized-key line, and the driver
loads RSA/Ed25519 private keys in the PEM formats supported by `ZtlsPK`
and unencrypted OpenSSH private-key format. Password-protected OpenSSH
private keys are out of scope. Run it against a separately installed reference `age` CLI in both
directions, then compare the decrypted output byte-for-byte. The driver
keeps the reference CLI and its interactive passphrase prompting out of the
ordinary unit suite.

`ZtlsBufferTest` covers TLS 1.3 negotiation, deliberately unsupported-version
rejection, SNI, ALPN, client authentication, PEM and DER certificate setup,
tickets and resumption, and allocator ownership. `ZtlsTxPacketTest` drives the
direct packet writer through reservation failure, partial cleanup, provider
geometry, and publication errors. It compares serial and vector operations
for the retained OpenSSL and CPU-supported Fusion suites.

`ZtlsRawHandshakeTest` drives the raw TLS 1.3 handshake used by Zquic. It
checks split and coalesced input, encryption levels, HelloRetryRequest,
ticket delivery, and caller-owned output at and below the required
capacity. It also checks wrong-epoch input and rejection of TLS KeyUpdate
on the QUIC path.

`ZtlsRxPacketTest` establishes an in-memory TLS 1.3 session and feeds distinct
packet-sized Rx buffers into the connection's private plaintext reservation.
It checks one stable allocation, one-byte and block-boundary fragmentation,
head/tail sentinels, publication only after authentication, bad tags, truncation
and provisional-data clearing on teardown. Sink tests also check insufficient
geometry, exception translation, ownership transfer and retained output lifetime.
The exact-capacity case verifies the contiguous receive API's borrowed destination.

`ZtlsRxStubTest` exercises the Ztls receive-context callback with a bounded
in-memory provider and an in-memory TLS 1.3 handshake. The fixture attaches the provider before acquiring
allocators. It uses separate Rx and TxTCP pools for registered packet backing
and injects a builtin Rx allocator for the builtin comparison. The test checks
head/tail sentinels, authentication gating on corruption, partial-record
close/reconnect, stale queued-input rejection, early input release and retained
plaintext lifetime after disconnect.

`ztlsrxpackettest` pairs native sockets with same-owner and separate-owner Rx,
and checks KeyUpdate, async signing, cancellation, and reuse after shutdown.
`ZtlsInitTest` checks independent standalone initialization, concurrent TLS
initialization, internal buffer growth, and the connection's aligned Rx and Tx
member groups.

`ZtlsEngineObjectTest` exercises virtual cipher, AEAD, hash and key-exchange
operations, hash clone/reset independence, HMAC snapshot rejection, partial
native initialization failure, both available Fusion widths, and destruction
through a secondary polymorphic base. It observes secret clearing before
release and checks the matching named heap release. `ZtlsRawHandshakeTest`
checks verifier retirement after success, malformed or unexpected messages,
reinitialization, teardown and certificate-provider rejection. It also covers
ECH acceptance/rejection, extension hooks and, when Brotli is available, actual
compressed-certificate handshakes.
