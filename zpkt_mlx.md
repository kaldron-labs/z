# Implementation plan for `zpkt/mlx` and `libZpkt_mlx`

Add an optional Linux plugin for raw Ethernet on NVIDIA/Mellanox adapters using the mlx5 provider. Applications select `libZpkt_mlx.so` through `Zpkt::Env`. The plugin uses `libibverbs` to create raw-packet resources and mlx5 Direct Verbs to drive their hardware queues from C++. The peer receives ordinary Ethernet frames and can use a conventional NIC. Packetio supplies a working reference for the device interface. Zpkt supplies the application interface, buffer lifetime, and scheduling model. [Packetio mlx5 backend](https://github.com/atoonk/packetio/blob/main/mlx5/README.md) · [Upstream mlx5 provider and public header](https://github.com/linux-rdma/rdma-core/tree/master/providers/mlx5) · [Zpkt contract](zpkt/INTERFACE.md)

The proposed first release uses one Rx queue, one Tx queue, the multiplexer's existing Rx and Tx owners, static hardware steering, and caller-computed TCP checksums. Use registered packet buffers and conventional, individually signaled sends. This gives a single low-rate packet the same completion guarantee as a full burst. Consider RSS, selective signaling, multi-packet sends, and checksum offload separately once the basic path has wire and latency results.

## 1. Build the module and open the right port

Add `zpkt/mlx/Makefile.am` with a private typed configuration, plugin factory, Nif, pool, and queue implementation. Install `libZpkt_mlx.la` with libtool's `-module -avoid-version` flags. In `configure.ac`, add a Linux-only `--with-mlx=yes|no` option, default off, and check `libibverbs` and `libmlx5` with pkg-config when enabled. Compile/link-check the Direct Verbs facilities actually used. Wire the option through `z.config`, register the new source-directory include alias and generated Makefile, and build `mlx` after `src` and before the tests. Keep provider headers private and link the native libraries on the plugin. Test both build configurations and loading the installed module through its C-linkage `ZpktPlugin` factory. [Build conventions](docs/BUILD.md) · [Existing plugin target](zpkt/dpdk/Makefile.am) · [Module traversal](zpkt/Makefile.am)

Use the owned, typed `interfaces` map keyed by Linux netdev name. Keep the default `hostNifInfo()` and `loopback()` policies. On an Env cache miss, use the supplied ifindex to resolve the RDMA device **and port** in the current network namespace, for example through the RDMA netlink port-to-netdev mapping. Verify the mlx5 provider, Ethernet link layer, and raw-packet capability. Reject missing or ambiguous mappings with the interface and native error in the diagnostic. Dual-port cards are an explicit test case. Open the verbs context and protection domain here. Return an initialized, stopped, unallocated Nif reporting the host MTU and MAC and one service Rx queue. [Plugin interface](zpkt/src/ZpktPlugin.hh) · [Env lookup](zpkt/src/ZpktEnv.cc) · [Named-interface factory pattern](zpkt/afp/ZpktAFP.cc)

## 2. Claim all ingress on the selected netdev

Opening the named interface claims its entire ingress. Acquire the shared socket-owned nftables netdev guard with `nifClaimIngress(ifindex)` before publishing the Nif. Keep the guard through allocation, activation failure, stop, restart and a refused finalization. Successful finalization closes the guard after retiring native resources. Opening requires the same netdev privileges as DPDK/mlx5. No IP, VLAN or transport selector is required. [Shared ingress guard](zpkt/src/ZpktIngress.cc) · [DPDK implementation](zpkt/dpdk/ZpktDpdkNif.cc)

```text
module libZpkt_mlx.so
interfaces {
  enp65s0f0 { rxDepth 512 }
}
```

At activation, validate the requested descriptor depth against the device, CQ and pool limits. Post the full Rx ring, then use `ibv_create_flow()` on the selected port and raw-packet QP with a normal Ethernet flow, wildcard Ethernet specification and trapping enabled. Keep the returned flow handle. This is the verbs counterpart of the DPDK ingress Ethernet wildcard and terminal queue-0 action. Cover all ingress admitted to that function, including unicast, multicast, broadcast, tagged frames and non-IP EtherTypes. A representor or VF receives only traffic delivered to that function. Use the nftables guard to suppress any remaining host copies. Return a start error if hardware cannot supply the complete receive path. On stop destroy the flow before dismantling the QP. If destruction fails, retain the handle and guard for retry. [Verbs flow specification](https://man7.org/linux/man-pages/man3/ibv_create_flow.3.html)

## 3. Allocate registered backing as one transaction

Implement `bufPool()`, `reserveTxPools()` and `alloc()` for the common Rx pool, each distinct TxTCP/TxUDP pool and internal Tx reserves. Calculate cache-line-aligned packet bases and strides, honor stronger alignment, and preserve each pool's logical size and head/tail room. Small control pools keep their requested geometry. Check size arithmetic and provision an Rx extent sufficient for the configured MTU and supported on-wire headers. Register DMA backing with the protection domain using local access appropriate to the direction. Store the local memory key, address-to-slot mapping and completion bookkeeping during setup. [Pool API](zi/src/ZiIOBuf.hh) · [Allocation rules](zpkt/GUIDELINES.md) · [Existing pool implementation](zpkt/afp/ZpktAfpPool.hh)

Hold provisional resources until every registration and index succeeds. On failure unwind in reverse order, then allow retry. A successful repeat with the identical pool set reuses the backing. Reject a changed or duplicate set. Retain pool references independently of the caller's intrusive list. An interior packet pointer must resolve directly to its slot and usable extent. Validate the submitted length against that extent. Pool exhaustion returns null. Final return can run on any thread, including while the device is stopped.

| Resource | Lifetime and owner |
| --- | --- |
| Verbs context and protection domain | Opened by named Nif creation. Released after the last dependent native object at finalization. |
| Shared netdev guard | Acquire at named open and release after successful finalization, including after an open without a start. |
| Packet backing, registration and slot identities | From successful allocation through finalization. Addresses remain valid across failed starts and stop/restart. |
| Raw-packet QP, completion queues, notification channel, wake fd and steering rule | Per run. Establish DMA quiescence before releasing posted slots. |
| Rx slot | The NIC owns a posted slot. A successful receive transfers it to the callback recipient. Explicit pool return makes it eligible for reposting by the Rx owner. |
| Tx slot | Caller allocation and device submission are independent leases. The last release recycles the slot exactly once. |

## 4. Bring up and service the hardware queues

At `start()`, create an `IBV_QPT_RAW_PACKET` queue pair with separate Rx and Tx completion queues (CQs). Bind it to the resolved port and drive the required QP state transitions. Obtain the queue layouts with `mlx5dv_init_obj()`. Use the returned SQ/RQ sizes, strides, CQ entry sizes, doorbell mappings and hardware-required inline header length. Select ordinary uncompressed completions, DMA into posted Rx buffers, and in-frame VLAN headers. Check the negotiated layout and modes before exposing readiness. Track capacity in hardware queue units, including sends that consume multiple work-queue blocks. Prepost Rx buffers before enabling steering. Publish readiness only after the run can service both directions. [Direct Verbs object ownership and layouts](https://man7.org/linux/man-pages/man3/mlx5dv_init_obj.3.html) · [Provider implementation](https://github.com/linux-rdma/rdma-core/tree/master/providers/mlx5)

**Queue correctness.** Give each queue and CQ a single owner. For a CQ acquired for direct access, that owner manages its consumer index and arming using the same cursor. Follow the provider's device-memory and MMIO ordering on x86-64 and ARM64 for descriptor publication, doorbell writes and completion reads. Track hardware counters through wrap and validate owner bits and completion opcodes before reading lengths or retiring slots. Keep a preallocated mapping from hardware work-request identity to slot. An unexpected or error completion enters the device error path. Unit-test descriptor bytes, wrap, and identity recovery independently of PCI hardware.

**Receive.** Drain a bounded batch on the Rx owner. For each valid completion, deliver the original frame and actual length excluding FCS. Check slot bounds and discard malformed or truncated frames. Preserve VLAN bytes. Use a borrowed `ZiRxBurst` for multiple deliveries and a null burst for a singleton. Refill from free slots. When the pool runs dry, an off-owner return wakes a parked receiver to repost. After the spin budget, publish the wait, arm one-shot CQ notification, recheck the CQ, pool returns and counted public wakes, then block on the completion channel and the Nif wake fd. Drain and acknowledge channel events, including spurious events, and rearm using the direct CQ state. Under sustained traffic check for wake and stop between bounded batches. [Rx and wake contract](zpkt/INTERFACE.md#packet-service) · [Common wake helpers](zpkt/src/Zpkt.cc)

**Transmit.** On the Tx owner, `txReady()` inspects the slot's submission lease before a caller rewrites retained bytes. For `send()`, validate the extent and available queue blocks, acquire that lease, write an Ethernet send descriptor referencing the registered frame, and ring the doorbell. Copy only the header prefix required inline by the device. Publish a scalar send immediately. A vector accepts the ordered leading prefix up to `MaxTxBatch`. Commit a short prefix even if the next entry fails. Refused entries acquire no new lease and retain their original bytes for retry. A duplicate of an accepted slot becomes eligible again when its earlier submission retires. Report `Zi::NotReady` for temporary pressure or an in-flight slot and `Zi::IOError` for a down device or invalid length. [Nif send and readiness API](zpkt/src/Zpkt.hh)

Request a completion for every accepted send. `pollTx()` drains the Tx CQ and releases the identified submission leases on the Tx owner. It returns the number retired, including when the last send was followed by an idle period. Derive `zeroCopy()` from the active registered-buffer DMA path. Report `tcpChksumOffload() == false` for this release and preserve caller-provided checksum bytes. Expose actual queue depths, pending work, packet and byte counts, drops/errors, port, catch-all steering state and effective modes through `allQueues()` and `status()`. Distinguish locally observed discards from hardware counters.

## 5. Make shutdown and restart safe

Follow the Nif engine's start/stop callbacks with the multiplexer scheduler running. Gate new work, remove ingress steering, wake and quiesce Rx, and drain accepted Tx on its owner. Gate off-owner notifications and wait for admitted writers before closing their fd. Acknowledge outstanding CQ events before destroying CQs. Reclaim posted Rx and outstanding Tx slots only after completion or successful native teardown has established the end of DMA. If quiescence cannot be established, retain the affected backing and its leases, report the error and prevent unsafe reuse. Invoke `txStopped` on the Tx owner after retirement. Cover stop from a receive callback through the asynchronous stop API. [Lifecycle contract](zpkt/INTERFACE.md#stop-and-finalization) · [I/O teardown](docs/IO.md#teardown)

Roll back partial activation in dependency order and preserve the allocated pool set for retry. Restart creates fresh queues and steering against the same registered backing. At `final()`, require stopped service and returned caller buffers, deregister memory before freeing it, release the protection domain and context, then retire the child from Env. Exercise finalization after open alone, allocation alone, failed start, and repeated runs.

## 6. Verify at three levels

| Checkpoint | Acceptance evidence |
| --- | --- |
| Build and hardware-independent TAP tests in `zpkt/test` | Build with mlx enabled and disabled. Load the plugin through Env. Use private synthetic queue memory and injected setup results to cover dual-port selection, failed registration and retry, ring wrap, variable-size sends, refused prefixes, duplicate slots, both lease-release orders, off-owner returns, lost-wake races and shutdown with an error completion. Check that common `libZpkt` has no direct verbs dependency. |
| Opt-in ConnectX test in `zpkt/itest` | Load the plugin against a provisioned port with an independent Ethernet peer. Verify exact untagged and VLAN-tagged bytes, minimum and full-MTU frames, unicast to multiple destinations, multicast, broadcast, ARP and IPv6 neighbor discovery, software TCP checksums, an isolated send retiring during idle, Rx exhaustion and wake, stop during traffic, and restart with caller-held backing at the same address. Compare sent and received frames at the peer and Z. Check that an independent Linux UDP socket receives before open and after finalization, stays silent from open through stop, and that another netdev continues to receive. Burst to the configured depth and then overflow it. Record the delivered count and hardware miss counters. Report absent hardware as a TAP skip and record actual hardware results separately. |
| Existing transport entry point | Select the module through Env, pass the Nif to Zutcp, obtain Rx/Tx allocators, and exercise TCP request/reply and UDP against an independent kernel peer on the claimed interface. Verify retransmission from retained backing, persistent pool addresses and the active checksum mode. Record NIC, firmware, driver, rdma-core version, MTU and CPU affinity. Measure single-packet latency and CPU cost before enabling batching optimizations. |

Use the repository's configured builds and `make -j8`, then run `make -C zpkt/test test` and the scoped integration targets. Run the deterministic suite under Clang ASan/LSan and a separate Memcheck build. For the physical fixture, document device access, `CAP_NET_ADMIN`, `CAP_NET_RAW`, sufficient locked memory, interface and peer selection, the effective catch-all steering mode and ring depth. Update the Zpkt interface, dependency and fixture documentation with the implemented configuration and verified hardware modes.
