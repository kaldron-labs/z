## Blockers

**C-1-1 · PROPOSE FIX · Public EAL declaration, lines 3–6 and 44–67.** An implementer cannot recover the required API from the cited brief in this checkout. Replace the reference with the complete namespace block from the archived “Adopted explicit EAL parameters” section, including all five enums, owned list type and member defaults. Keep the existing explicit initialization and duplicate-option rules. Document the spelling of each argv option alongside its member, including special cases such as maxSIMDBits mapping to `--force-max-simd-bitwidth`. Test omitted numeric values separately from explicit zero. [Archived declaration](dpdk_plan_transcript.md#L28632) · [DPDK 25.11 EAL options](https://doc.dpdk.org/guides-25.11/linux_gsg/linux_eal_parameters.html)

**C-1-2 · PROPOSE FIX · Backend lifecycle, lines 20–22, 163–171 and 305–318.** Replace the obsolete virtual-method list and recreation instruction. Stopped backend init validates and retains configuration. Backend start acquires the exclusive port, configures queues and starts the device. Report started(true) only after setup succeeds. On failure, unwind acquired resources, preserve the first error, then report started(false) once. Stop gates service, wakes Rx, waits for its outstanding invocation and releases the stopped port when driver access is quiescent. Use the existing Tx owner for outstanding retirement work. Complete the engine callback once, then allow stopped-only final to release retained setup. Zutcp restarts its retained backend through init and start. Test this separately from a fresh backend acquiring the same released port. [Backend API](../../zpkt/src/Zpkt.hh#L70) · [Zutcp lifecycle](../../zutcp/src/Zutcp.cc#L989)

**R-1-1 / C-1-3 · PROPOSE FIX · Tx credit retirement, lines 129–144 and 163–170.** Zutcp waits for the last credit before requesting backend stop. A cleanup call can be unsupported, and its count alone misses references already released through another path. Proposed ownership rule for single-segment Tx buffers:

1. Keep one native reference owned by the pool slot while the caller holds its lease or Tx tracks a submission. Represent these two reasons separately in private slot state. Synchronize the last caller return with Tx retirement so exactly one side releases the slot reference.
2. Before a burst, add one device reference. Roll it back on refusal. On acceptance, track the slot once in bounded Tx-owned storage. Keep its address stable and prevent reuse or resubmission while tracked.
3. Poll for driver progress where supported. Visit outstanding slots with a rotating, bounded budget. Once the native reference count falls to the pool slot's single reference, remove the submission and report one credit. The ring fixture's peer releases the device reference after consuming the outgoing packet. The caller may release its lease before or after that event.
4. Require a driver path that releases the final packet independently or supports driving that release during polling. For a mode without either guarantee, fail setup before accepting traffic. Treat a runtime device error as a failure requiring quiescence and error propagation. Exercise the final lone packet with and without a retained caller lease, delayed peer consumption, saturation, immediate completion and stop. Demonstrate exactly one credit and no reuse before both obligations end.

This is a proposed mechanism. The software fixtures must demonstrate it, and admitting another PMD requires evidence for its last-packet behavior. [Zutcp stop gate](../../zutcp/src/Zutcp.cc#L1060) · [DPDK Tx cleanup contract](https://doc.dpdk.org/api-25.11/rte__ethdev_8h.html)

| R-1-2 · PROPOSE FIX | **52–60, 106–113, 313–316.** A held buffer can outlive an instance. Give the native pool owner a lease on initialized EAL resources, retained through final backing return.
