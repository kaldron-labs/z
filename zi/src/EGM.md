# Zi source contract

## Overview

Platform files and processes, scheduled network I/O and buffers, stream framing, shared-memory rings, logging, DNS, and I/O telemetry.

## Interface

- `ZiFile`, `ZiStat`, and `ZiMMapFile` provide file/vector/positional I/O, filesystem metadata, mapping and path APIs; `FileTxStream` adapts buffered printable output. [ZiFile.hh:ZiFile] [ZiFile.hh:ZiStat] [ZiFile.hh:ZiMMapFile] [ZiFileTxStream.hh:FileTxStream]
- `IOBuf` and allocators expose polymorphic byte storage, growth, prepend/append and streaming with builtin or plugin allocation. `ZiGlob` caches directory entries for prefix completion; heap/hash tuning loads and saves CSV. [ZiIOBuf.hh:IOBuf] [ZiGlob.hh:ZiGlob] [ZiHashTune.hh:load] [ZiHeapTune.hh:load]
- `ZiMultiplex` exposes scheduler-backed listen/connect/UDP, telemetry and plugin registration; `ZiConnection` exposes receive/send, draining sync and teardown hooks. `ZiMxPlugin` supplies user-mode network hooks; `ZiMxParams`/`ZiCxnOptions` configure threads and endpoints. [ZiMultiplex.hh:ZiMultiplex] [ZiMultiplex.hh:ZiConnection] [ZiMultiplex.hh:ZiMxPlugin]
- `ZiPIDFile` owns a process PID file through initialization/finalization and exposes OK/Error/Running results. [ZiPIDFile.hh:ZiPIDFile]
- `ZiEvent::Loop` integrates scheduler/shard readiness callbacks. `ZiLog` exposes singleton severity/sink/queue/lifecycle APIs. `ZiModule` loads and resolves dynamic libraries; telemetry Mx/Connection/Pool interfaces expose snapshots and watches. [ZiEventLoop.hh:Loop] [ZiLog.hh:ZiLog] [ZiModule.hh:ZiModule] [ZtcMx.hh:MxMgr] [ZtcPool.hh:Pool]
- Platform helpers expose native handle/socket/path types and host/user identity; ZiProgram reads process-name/command-line metadata. `ZiResolver` provides asynchronous address, reverse-name, DNS and TXT queries with cancellable retained handles. [ZiPlatform.hh:Handle] [ZiProgram.cc:name] [ZiResolver.hh:Main]
- `ZiRxContext`/`ZiTxContext` retain backing buffers, callbacks and datagram metadata; completion releases backing/callbacks and disconnect also sets its result. `ZiIP`/`ZiSockAddr` represent native addresses and provide parsing, classification, comparison and printing. [ZiIOContext.hh:ZiRxContext] [ZiIOContext.hh:ZiTxContext] [ZiIP.hh:ZiIP] [ZiIP.hh:ZiSockAddr]
- `ZiRing` specializes ZmRing for shared-memory broadcast with multiple readers and configurable writer/message modes. `ZiRx` supplies transport and memory framing, with owning asynchronous or borrowed synchronous body delivery. [ZiRing.hh:ZiRing] [ZiRx.hh:ZiRx]
- Move-only `RxStream`/`RxLayer` manage queued framing with scan/consume/extract/splice. `ZiTx` manages owning output queues; `TxStream`/`TxLayer` format synchronously and compose frame allocation/preparation. Hub/Link telemetry exposes commands, enumeration and watches. [ZiRxStream.hh:RxStream] [ZiRxStream.hh:RxLayer] [ZiTx.hh:ZiTx] [ZiTxStream.hh:TxStream] [ZiTxStream.hh:TxLayer] [ZtcHub.hh:HubMgr] [ZtcLink.hh:Link]
- `ZiCSV` supplies bounded schema-based file readers and push/pull writers; `ZiDir` scans directories with explicit error/EOF results. `ZiAssert` uses debug assertions or fatal backtrace logging plus caller fallback. [ZiCSV.hh:PushFile] [ZiCSV.hh:Reader] [ZiDir.hh:ZiDir] [ZiAssert.hh:ZiAssert]
- The manifest builds `libZi.la` and installs file/network/logging/stream/telemetry headers, linking Zf, Ze, Zt, Zm, Zu and configured platform libraries. [Makefile.am:lib_LTLIBRARIES] [Makefile.am:pkginclude_HEADERS]

## Invariants

- File copies shadow the handle; moves null the source, and destruction closes only with GC. FileTxStream borrows its file and flushes on destruction. [ZiFile.hh:ZiFile] [ZiFileTxStream.hh:FileTxStream]
- IOBuf is immovable; allocator/owner pointers are borrowed and must survive it. Growth clears registration; plugin allocators retain their plugin and route registered frees to it. Empty length and allocation failure are distinct state. [ZiIOBuf.hh:IOBuf] [ZiIOBuf.hh:IOBufPluginAllocator]
- Receive/listen/connect paths belong to Rx; send and plugin disconnect/close belong to Tx; sync is control-thread work. Allocator/plugin registration is stopped-only and application-serialized with lifecycle. Telemetry reads may observe unclean snapshots. [ZiMultiplex.hh:ZiConnection] [ZiMultiplex.hh:ZiMxPlugin] [ZiMultiplex.hh:allocator]
- Event loops borrow their scheduler. Logging retains one sink reference and locks its queue. Telemetry APIs pass raw object pointers or borrowed snapshot spans. Module GC controls automatic unloading; handle/flag getters are unlocked. [ZiEventLoop.hh:Loop] [ZiLog.hh:Queue] [ZtcMx.hh:MxMgr] [ZiModule.hh:ZiModule]
- Resolver admission is serialized with shutdown; accepted tasks run on its dedicated scheduler, but literal/rejected results can call inline. Start/stop are blocking main-thread operations forbidden inside callbacks. Cancellation suppresses delivery while native requests finish; TXT spans borrow temporary DNS storage. [ZiResolver.hh:invoke_] [ZiResolver.hh:start] [ZiResolver.cc:ZiResolver_AQueryCB] [ZiResolver.cc:txt_]
- Rx callback true stops immediate processing without disarming. IP numeric parsing is bounded, performs no DNS and preserves output on failure; socket address sync is required after native-family changes. Log events select the current sink at execution time. [ZiIOContext.hh:ZiRxContext] [ZiIP.cc:parse] [ZiIP.hh:sync] [ZiLog.hh:log_]
- Ring requested/opened sizes must match; single-writer ownership uses PID and process start time. Receive callbacks retain local backing, replenish the transport slot before parsing, and guard against overwriting replacement callbacks. Incomplete transport frames move to App-owned accumulation. [ZiRing.hh:openSize_] [ZiRing.hh:open_] [ZiRx.hh:arm] [ZiRx.hh:frames]
- Receive scan leaves ownership unchanged; consume borrows complete contiguous data synchronously, gathering fragments temporarily. Extract/splice transfer nodes or copy boundaries as required. Tx owners are raw pointers; abort excludes the current head. Concrete streams must flush before callback state dies; base destruction only releases buffers. [ZiRxStream.hh:scan_] [ZiRxStream.hh:consume] [ZiRxStream.hh:extract] [ZiTx.hh:send] [ZiTx.hh:abort] [ZiTxStream.hh:TxStream]
- Event-loop registration/removal is owner-thread-only, priming callbacks can run before insertion, and Linux edge-triggered consumers must drain nonblocking I/O. Stop drains before completion; final alone does not stop resources. [ZiEventLoop.cc:addSocket] [ZiEventLoop.cc:run_] [ZiEventLoop.cc:stop] [ZiEventLoop.cc:final]
- Successful file opens add GC; explicit close closes any non-shadow handle and then clears it, while shadow close detaches. Standard handles default without GC. Shared-memory opens require positive length and round backing capacity to platform granularity. [ZiFile.cc:open_] [ZiFile.cc:close] [ZiFile.cc:openStdIn]
- Connect/listen/UDP calls reject stopped multiplexers and otherwise dispatch to Rx; setup rechecks running state and allocator ownership. Connection factories return caller-derived connections, retained before connected notification. Enumeration retains connections before callback delivery. [ZiMultiplex.cc:connect] [ZiMultiplex.cc:udp_] [ZiMultiplex.cc:executedConnect] [ZiMultiplex.cc:allCxns_]
- Rx appends to available buffer space; IOCP holds one pending buffer and restores ownership before callback delivery. Tx preserves partial-send offsets and callbacks can synchronously replace the next message. Disconnect disables Tx then retains a connection across the Rx handoff. [ZiMultiplex.cc:recv] [ZiMultiplex.cc:overlappedRecv] [ZiMultiplex.cc:send] [ZiMultiplex.cc:executedSend] [ZiMultiplex.cc:disconnect_1]
- Close completes Tx then retains the connection across Rx cleanup; IOCP defers final notification until pending receive cancellation finishes. Multiplexer stop drains connections, waits for plugin stop, stops its scheduler, then releases native resources. [ZiMultiplex.cc:close_1] [ZiMultiplex.cc:notifyDisconnected] [ZiMultiplex.cc:stop__]

## Side Effects

- Stream overflow flushes to the file; IOBuf growth allocates and moves bytes while latching failures. Glob reads directories and returns borrowed entries. Tuning loads configure heap/hash managers; saves create/truncate files selected by Z_HEAPTUNE/Z_HASHTUNE and may throw. [ZiFileTxStream.hh:flush] [ZiIOBuf.hh:ensure] [ZiGlob.cc:init] [ZiHeapTune.hh:save] [ZiHashTune.hh:save]
- PID initialization validates paths, creates directories/files, checks process liveness and may retry with sleeps. It writes/publishes the current PID; final removes owned files only when current contents match that PID, then resets state. [ZiPIDFile.cc:init] [ZiPIDFile.cc:resolvePath] [ZiPIDFile.cc:final]
- Dynamic modules use platform loading/resolution/unloading, with global/lazy Unix linkage and optional deep binding. Log filtering precedes enqueue; formatting invokes sink callbacks and backtrace wrappers capture traces. [ZiModule.cc:load] [ZiModule.cc:resolve] [ZiLog.hh:log_] [ZiLog.hh:ZiLogBT]
- Resolver initializes c-ares, opens channels/readiness/timers and performs hosts/DNS lookup. Stop closes admission, cancels native requests, drains readiness work and stops the scheduler; final joins before callback destinations may be destroyed. [ZiResolver.cc:openChannel_] [ZiResolver.cc:stopRx_] [ZiResolver.cc:final_]
- IP resolve/name bridge asynchronous DNS with blocking waits and cannot run inside resolver callbacks. Logging lazily starts a worker, queues through a ring/FIFO and drains before join; sinks rotate/write files, use system logging or invoke callbacks. Sink rotation runs directly on the caller thread. [ZiIP.cc:resolve_] [ZiIP.cc:name] [ZiLog.cc:log__] [ZiLog.cc:stop_] [ZiLog.cc:ZiFileSink] [ZiLog.cc:age_]
- Ring opens named control/data mappings with optional mirrored mapping/NUMA binding; wait uses shared futexes or named semaphores. Writer GC probes reader liveness and releases dead slots; kill signals blocking readers and waits. Receive framing allocates/copies where ownership requires it and disconnects on parse/growth errors. [ZiRing.cc:CtrlMem] [ZiRing.cc:MirrorMem] [ZiRing.cc:Blocker] [ZiRing.hh:gc] [ZiRing.hh:kill] [ZiRx.hh:frames]
- Formatting/frame preparation runs during stream insertion and may immediately send on rollover. Physical send setup and completion run on Tx; queue overflow/errors report failed completion. Hub mutation watchers run under its write lock, enumeration under its read lock, and snapshot consumers after unlocking; unwatch synchronizes with watchers. [ZiTxStream.hh:append] [ZiTxStream.hh:sendBuf_] [ZiTx.hh:send] [ZtcHub.cc:ZtcHubMgr_]
- Daemon startup can change process credentials/umask, fork or relaunch, exit the parent and establish PID ownership. Directory operations open/close OS enumeration resources. Event loops allocate wake/polling resources and drain them on stop; removing Windows handles closes them, while socket removal leaves sockets open. CSV writers create/append/replace files. [ZiDaemon.cc:init] [ZiDir.cc:open] [ZiEventLoop.cc:stop_0] [ZiCSV.hh:PushFile]
- Files perform native scalar/vector/positional I/O, seeks and truncation; mmap opens backing storage and optionally maps it twice adjacently. Mapping close unmaps and releases backing ownership. Failed operations retain native error state; successful calls do not universally clear previous errors. [ZiFile.cc:read] [ZiFile.cc:write] [ZiFile.cc:truncate] [ZiFile.cc:ZiMMapFile::mmap] [ZiFile.cc:ZiMMapFile::close]
- Socket setup binds/connects, configures multicast/TOS and readiness modes, and closes sockets on setup failure. Global multiplexer watchers execute under its write lock, enumeration under its read lock, and snapshot consumers after unlocking. Connection telemetry queries kernel queues/buffers; destruction warns and closes any remaining socket. [ZiMultiplex.cc:udp_] [ZiMultiplex.cc:ZiMxMgr_] [ZiMultiplex.cc:telemetry] [ZiMultiplex.cc:ZiConnection::~ZiConnection]
- Listeners drain/replenish platform accept work; socket initialization sets buffering/reuse/keepalive/linger/Nagle/readiness. Receive/send callbacks update context and can rearm or close; sync blocks while Tx drains. Stop-listening closes sockets; disconnect shuts down TCP after clearing Rx/Tx contexts. [ZiMultiplex.cc:accept] [ZiMultiplex.cc:overlappedAccept] [ZiMultiplex.cc:initSocket] [ZiMultiplex.cc:executedRecv] [ZiMultiplex.cc:sync] [ZiMultiplex.cc:stopListening_] [ZiMultiplex.cc:disconnect_2]
- Filesystem helpers mutate permissions, synchronize mappings/files, copy/remove/rename paths, recurse without intentionally traversing links, and rotate aged files. Multiplexer construction/start configures signals and native readiness resources; receive dispatch posts Tx work with retained connections. [ZiFile.cc:mode] [ZiFile.cc:copy] [ZiFile.cc:removeTree_] [ZiFile.cc:age_] [ZiMultiplex.cc:start__] [ZiMultiplex.cc:rx]
